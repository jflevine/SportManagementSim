# Signal Leak Simple: draft optional submission pilot

**Not deployed, not configured, not authorized for real collection. Canvas is official.**
The entire existing game and local download work without a backend or sign-in. Finish instructions are: download the handoff, copy all text, paste into Canvas Signal Leak Check → Text Entry, then click Submit Assignment. The separately gated pilot appears only after finishing, never sends automatically, and sends only on an explicit opt-in and action. No collection on revisits, and signing in is not required to complete the game.

## Proposed contract
A new Edge Function slug `spm370-signal-leak-simple-pilot` receives POST JSON `{attemptId,choices,answers}` under an approved short-lived bearer session. The server verifies the bearer against Supabase Auth and the institution-approved provider, then requires the returned verified account UUID in a separate course roster. No student-entered names, emails, addresses or account handles. Instructor visibility is via the existing verified restricted Supabase project dashboard; no student-facing read route, no shared link, no public inquiry. Before configuring, confirm that same project's access is appropriately restricted for identified student work and that the instructor has authorized access to the two pilot tables (including a private UUID-to-enrollment mapping). Table rows record the verified UUID, choices, written answers, random receipt and server timestamp; this is identified educational work, not anonymous.

There is one immutable optional handoff per roster UUID while this pilot is run. A stable attempt ID, the exact frozen answers and local account binding are stored in the browser only when the student first chooses to send. No token is persisted by the adapter. A failed or uncertain response never displays “saved”; retry with the same browser, verified account and snapshot returns the same receipt if already committed. A different retry returns conflict, does not replace the saved record, and the correct instruction is to submit in Canvas. A lost draft on a different device is not retrievable in the student page. Browser failure or corrupt local retry storage does not block Canvas or downloads.

## Release gates
1. Confirm La Salle-approved authentication, named instructor access, existing project permission scope, roster source, notice and data handling, retention/deletion and operational rate limits. Do not change shared Auth, RLS, network, credentials, roles or existing project settings absent appropriate approval. If shared project visibility is inappropriate, keep Canvas-only and use an approved isolated environment. Do not provision an auth provider solely to make this demo work.
2. Draft code needs the institution-approved provider configured and a separate approved adapter in `config.mjs` to acquire a signed session. This version intentionally has no provider implementation or credentials. Verify genuine issuer/session provenance and role/roster mapping in the selected environment (the auth record's provider or email alone is not enrollment). Email verification is not a substitute for roster membership. Do not rely on CORS as authentication. Only the exact approved HTTPS origin is accepted. Separate security review of the gateway configuration, trusted origin boundaries and rate limiting is required before enabling. Avoid putting the live student frontend on an origin shared with other scripts unless approved.
3. Verify the migration and live-role permissions with synthetic identities on an approved separate staging database. Exercise duplicate concurrent retries, post-commit response loss, no roster, no pilot table access for anon/ordinary authenticated users, valid instructor dashboard retrieval, mobile and Canvas-only fallback. Ensure logs omit request bodies, auth tokens and identifying data. All these are rollout gates, not this branch's test claims.
4. Only after the gates pass and the user confirms any required changes, consider deploying the new function and migration. Keep both flags off until then. Do not alter the older `signal-leak` Edge Function, shared simkit, any MGT 340 path, or the Canvas submission workflow. Disable the server flag to stop collection if anything fails; existing local gameplay remains available.

## Draft validation
Run `node --test pilot/pilot.test.mjs` from the game directory. Tests use fictional input and an in-memory store, not deployed services or actual student accounts. No actual SQL/auth/browser/instructor signoff is implied.
