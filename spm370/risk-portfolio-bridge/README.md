# SPM370 Risk and the connected stakeholder

Draft, not deployed. Open index.html locally. All assets are local and editable. No install is required. A static host could serve this directory after review; no backend exists here.

## Design
The student advises a collegiate program before the next late scrim. The task is identifying connected risks, assessing a defined outcome, prioritizing action and comparing feasible controls. The product is a risk recommendation rather than a conversation game. Twelve combined response boxes keep this a warm-up, not a second portfolio. Estimated 25–35 minutes, untested with students. Independent pace, no countdown or partner required.

The chapter supplies a coach who saw a player's stressed messages, a late schedule, and playoff pressure. Students must not invent diagnosis, age, injury, policy, or jurisdiction. Player/program perspectives differ. A schedule control can leave unofficial sessions unresolved; a check-in can leave the schedule unchanged. These contrasts support debrief without fabricated simulation consequences.

Claude simkit's AUTHORING_GUIDE and The Report README informed the format choice: build the professional work product rather than copying a chat interface. This is a guided register, not a lifelike simulation; it does not use simkit or claim a server-side event ledger. No shared engine, registry, backend, existing activity, or production data was changed.

## Teacher use
Review the opening mini-lesson and all prompts. Preserve the original Thursday deck and worksheet. For an individual remote lesson, offer this page plus the chapter/slides. For class use, students can compare two different priority decisions after completing it individually. Ask: Did you rate the same consequence? What missing evidence could change your ordering? Which control protects one stakeholder while leaving exposure for the other?

Do not assign the page until the access and collection workflow is chosen and tested. Downloading a text file or printing to PDF does NOT submit it. The page tells students to follow your separate instructions. It has no deadline, grade, or accommodations policy. A student need not disclose any personal condition. The worked example is expandable after the recommendation; it is not access-controlled.

For reliable collection without a new service, approve a Canvas upload route, tell students to download their record, then verify a fictional submission from a student view. If using a backend later, implement authentication, receipt, retry handling and instructor retrieval before claiming submission support. Browser storage is a convenience only and may fail or be cleared. No names or sensitive information are requested.
